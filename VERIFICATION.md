## Release Audit: Secrets and PII (2026-10-25)

Audit run on the git-tracked file set (`git ls-files` and a case-insensitive
`git grep` at HEAD) and over the full patch history (`git log --all -p`), for
`checc`, `C:\\Users\\` paths, local host names, `ghp_`, `gho_`,
`github_pat_`, `sk-`, `AIza`, `API_KEY` and personal e-mail patterns:

- **Tracked files at HEAD: 0 hits.** No absolute personal path, host name,
  token or personal e-mail appears in any versioned file.
- **History: 0 leaks of credentials.** Every `sk-` match is a false positive
  of the string "task-manager". Token patterns (`ghp_`, `gho_`,
  `github_pat_`, `AIza`, `BEGIN PRIVATE KEY`) return 0 matches.
- **History: PII only in metadata, not in content.** The author identity
  `PieroFra <checc...@gmail.com>` appears in commit metadata and the personal
  absolute path `C:\\Users\\...` appears inside blobs of historical document
  versions that were already replaced with neutral paths in the current
  files; removing it would require a history rewrite or force-push, so the
  finding is recorded here instead. The e-mail is superseded in repo settings
  by the public GitHub identity used by the release commands.
- The packaging script header was changed from embedding `$env:COMPUTERNAME`
  to a plain `deterministic build` marker, so no host name is ever written
  into `dist/.files.txt`.
